# 保管庫の定期作業

> ⚠️**立ち上げ期（記事が一定数貯まるまで）は、定期メンテよりロードマップのSTEP進行を優先する。**
> 現在＝STEP 2.5（ブランディング）。記事はまだ1本もない＝**下のワークフロー1・4・5・6はまだ出番がない。**

| ワークフロー | トリガー | 頻度 |
|---|---|---|
| 1. 定期メンテナンス | 「定期メンテやって」 | 月1（記事が貯まってから） |
| 2. 記事生成 | 「〜で記事を書いて」 | 随時 → `article` スキル |
| 3. 個別取り込み | 「`[ファイル名]` を取り込んで」 | 随時 |
| 4. コンテンツ分析 | 「これまでの記事を分析して」 | 随時 |
| 5. 外部ナレッジ巡回 | 「巡回して」 | 月次 |
| 6. 四半期レビュー | 「四半期レビューやって」 | 3ヶ月に1回 |

## 3. 個別取り込み（今すぐ使える唯一のもの）

1. `raw/` の対象ファイルを読む（**編集しない**）
2. 要点を `wiki/sources/` に要約ページとして作る
3. 関連する `wiki/concepts/`・`wiki/entities/`・`wiki/persona/` を更新する
4. `[[WikiLink]]` で相互リンクを張る
5. 既存の記述と矛盾したら**明示的にフラグを立てる**（勝手に上書きしない）
6. `logs/activity.md` に追記

## 1. 定期メンテナンス（記事が貯まってから）

1. `wiki/index.md` のステータスを実態に合わせる
2. stale になった文書にマークを入れる（**中身は消さず、経緯として残す**）
3. `wiki/performance-log.md` に実績を記録する
4. 実在クエリに当たっている記事が何本あるかを数える（★**本数より重要**）
5. `logs/activity.md` に追記＋git commit

## 6. 四半期レビュー

- ロードマップのSTEP進行を見直す
- [[00_設定/事業計画・収支予測_2026-2028]] の判定に照らす
- ⚠️**本人決定＝管理しない。本数ノルマ・時間上限・進捗の催促はしない。** レビューは事実の確認であって、催促の場ではない。

## セッション終了時（毎回・例外なし）

1. `logs/activity.md` に追記（**決定・成果物のファイルパス・次アクション**）
2. `git commit`
3. **見直し＋所感レポート**（自分で穴を見つけて正直に報告する）
