# 調べるときの作法

## 掟（例外なし）

1. ★**実査していないSERP・数値・出典を書かない。** 検索した結果とURLだけを記録する。**推測での穴埋めは禁止。**
2. ★**発見を1つ得たら、結論に飛ぶ前に「決まっていること」（[[00_設定/引き継ぎ_Opus_2026-08]] §3）と突き合わせる。** 矛盾しないと確認できるまで結論にしない。
   ※2026-08-03に、この手順を守らず**1セッションで8回結論を撤回した**。
3. ★**案を出すときは「これはClaudeの推測」と明示する。** 本人決定・実測と同じ重さで並べない。
4. ⚠️**ただし「調べずに既存の材料だけで済ませる」のも同じ失敗**（本人指摘）。**調べる。ただし結論を急がない。**
5. **同じ失敗2回で撤退**し、状況を `logs/activity.md` に書いて止まる（無限リトライしない）。

## ★出典の質（この見分けが一番効く）

| 重い | 軽い・要割引 |
|---|---|
| **一次情報**（Google公式ドキュメント・官公庁・企業の規約ページ） | 解釈を挟んだ二次記事 |
| **財務が検証された数字**（Empire Flippers＝2〜4週間かけてGAでトラフィック・決済事業者で収益を検証・盗用チェックまでやる） | ⚠️**Flippa＝自己申告で未検証** |
| **本人が公開している収益**（levels.io など） | 「事例」として他人が書いた数字 |
| 独立した複数ソースで一致する方向 | 単一ソース |
| ❌**採用しない** | ★**教材・コンサルを売っている人の数字**。⚠️「AIで稼ぐ」系の検索上位（greyjournal / crazyburst / widejournal / noteの「AIマネタイズ専門家」系）は**それ自体が出典のないAI量産記事**だった（2026-08-04実査） |

## ★直接検索が効かないときの切り口4種

**「成功事例」で直接引くと、夢を売る人しか出てこない。成功している運営者は宣伝しない＝競合を呼ぶだけだから。**

| # | 切り口 | なぜ効くか |
|---|---|---|
| **1** | **金が実際に動いた場所を見る** | サイト売買市場・決算・買い手の判断基準。**売買には財務の検証が入る** |
| **2** | **失敗の記録を探す**（成功談ではなく） | **人は失敗の方を、正直に、数字つきで書く** |
| **3** | **運営者の言葉で検索する** | 「AIで稼ぐ」ではなく `commodity content` / `content moat` / `RPM` / `sessions` / `E-E-A-T`。**マーケターの言葉と運営者の言葉は違う** |
| **4** | **一次情報が何を名指ししているかを見る** | 業者の解釈を経由しない |

※この4種は本人の指導（2026-08-04「工夫した切り口が大事」）から言語化した。

