## 全体の進め方（順番厳守）

```
保管庫設計 → リサーチ → ペルソナ確定 → コンテンツ設計 → デザイン → 記事生成 → 公開・運用
   ✅           ✅          ✅            ✅            🔄(設計✅/実装残) ⬜      ⬜
```

前段が固まる前に次へ進まない。特に **デザインはペルソナ確定後** に着手する（ユーザー方針）。

## 継続運用（完成後・社不ライフと並行）

### 並行運用の原則
- 散歩する主夫と社不ライフは**独立した2つの保管庫**。メンテは別々に回す。
- 立ち上げ期は散歩する主夫に集中投下。社不ライフは維持モード。
- ノウハウ（テンプレ・ペルソナ手法・デザイン部品）は流用、コンテンツ/内部リンクは混ぜない。

### 定期サイクル（CLAUDE.md ワークフロー準拠）
| サイクル | 内容 | トリガー |
|---|---|---|
| 月1 | 定期メンテ（新規記事取り込み・リライト反映・ヘルスチェック・YMYL期限） | 「定期メンテやって」 |
| 月次 | 外部ナレッジ巡回（制度改正・新統計・競合）→ questions更新 | 「巡回して」 |
| 随時 | 記事生成（ワークフロー2） | 「〜で記事書いて」 |
| 3ヶ月 | 四半期レビュー（成長量・太った/痩せたピラー・需要推移の再確認） | 「四半期レビューやって」 |
| 半年 | ペルソナ・research-summary の再検証（需要が立ち上がったか） | 半年メンテ時 |

### 立ち上げ期の特例
記事が15本前後貯まるまでは、月次定期メンテより**ロードマップのフェーズ進行を優先**する。
