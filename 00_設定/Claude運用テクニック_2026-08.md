# Claude運用テクニック

2026-08-04 の実査。手順を `.claude/skills/` に出した記録もあるが、そのディレクトリは 2026-09 に外した。本文は当時のまま。

## §1 ★★★最重要の発見＝**CLAUDE.mdが長すぎることが、8回撤回の機械的な原因**

公式ドキュメントに、そのままの記述がある：

> **「CLAUDE.mdが長すぎると、Claudeは半分を無視する。重要なルールがノイズに埋もれるから。」**
> **「Claudeがルールに反することを繰り返すなら、たいていファイルが長すぎて、そのルールが埋もれている。」**
> **「肥大したCLAUDE.mdは、Claudeが実際の指示を無視する原因になる。」**

**この保管庫で起きたこと：**

| | |
|---|---|
| **CLAUDE.md の長さ** | **227行** |
| ルール | 「**発見を1つ得たら、結論に飛ぶ前に確定事項と突き合わせる**」＝**書いてある** |
| 実際 | ★**2026-08-03に1セッションで8回撤回。自分で気づいたものはゼロ** |

> ★**「Claudeが気をつける」で直そうとしていたが、公式の診断は「ファイルが長すぎるから埋もれている」。**
> ★**そして対策も書いてある＝「常に必要な事実」だけCLAUDE.mdに残し、「たまにしか要らない手順」はスキルに出す。スキルは使うときだけ読み込まれるので、普段のコストがゼロ。**

### 1-1. 公式が言う「CLAUDE.mdに入れるもの／入れないもの」

| ✅入れる | ❌入れない |
|---|---|
| Claudeが推測できないコマンド | 読めばわかること |
| 既定と違うルール | 標準的な慣習 |
| **プロジェクト固有の決定事項** | **詳細なドキュメント（リンクにする）** |
| よくある落とし穴・非自明な挙動 | 長い説明・チュートリアル |
| リポジトリの作法 | **頻繁に変わる情報** |

**判定基準＝「この行を消したらClaudeがミスをするか？ しないなら消す。」**

### 1-2. ★この保管庫のCLAUDE.mdを、この基準で仕分けると

| 現在の中身 | 判定 |
|---|---|
| **現在の状態（今どのSTEP・B2の結論）** | ⚠️**頻繁に変わる**＝公式の「入れない」に該当。**引き継ぎ書とロードマップが正なので、CLAUDE.mdはそこへのリンクだけでよい** |
| **決まっていること（本人決定）** | ✅**残す**（ただし引き継ぎ書§3と二重管理になっている） |
| **Claudeへの警告（8回撤回・掟）** | ✅**残す。むしろ埋もれないよう最上部に短く** |
| フォルダ構成 | ❌**読めばわかる**＝消す |
| YMYL区分の表 | ⚠️**日本語版の棚上げ資産。英語圏版では未使用**＝スキルへ |
| ワークフロー6種の表 | ⚠️**手順＝スキルへ** |
| 記事生成の6ステップ | ⚠️**手順＝スキルへ**（記事を書くときだけ要る） |
| トーン・文体ルール（暫定） | ⚠️**voice-guide-enと重複**＝リンクにする |
| 社不ライフとの関係 | ⚠️**教訓と資産に書いてある**＝リンクにする |

> ★**要点＝227行のうち、常時必要なのはおそらく50〜70行。残りは「記事を書くとき」「実装するとき」にだけ要る手順。**

## §3-2 ★公式ドキュメント以外のテクニック（[Claude Code パワーユーザーTips](https://support.claude.com/en/articles/14554000-claude-code-power-user-tips)ほか・2026-08-04実査）

**この保管庫で実際に効きそうなものだけ拾った。**

| テクニック | この保管庫での使いどころ |
|---|---|
| ★★**訂正したら、その場で当時の CLAUDE.md を更新していた** | 「その間違いを繰り返さないよう更新して」と言っていた。8回撤回はこれをやっていれば減っていた、という記録 |
| ★★**`PostCompact` フック**＝**圧縮の後に、重要な指示を再注入する** | ★**2026-08-04に設置済み**（本人決定と現在地を圧縮後に再注入）。**CLAUDE.mdに「圧縮時はこれを残して」と書くのは助言だが、フックは確実** |
| ★**`/effort`**（low / medium / high / xhigh / max / auto） | **重いリサーチはxhigh、軽い整理はlow**。使い分けでコストと質を調整できる |
| ★**`/btw`**＝**文脈を汚さずに横道の質問をする** | 答えは消せるオーバーレイに出て会話履歴に入らない。**「ちょっと聞きたいだけ」でコンテキストを太らせない** |
| ★**`/context`**＝今のコンテキスト使用量を見る | **長いセッションが多いこのプロジェクト向き。**「そろそろ `/clear` か」の判断に使う |
| ★**強く押す言い方** | 「**この変更について私を問い詰めて（grill me）。私が合格するまで進めるな**」／「**これが動くことを証明して**」／「**今わかっていること全部を踏まえて、これを捨ててエレガントな方をやり直して**」 |
| ★**`/rewind`（Esc 2回）** | 危ないことを試して、ダメなら巻き戻す。**「試す→戻す」が安全にできる** |
| ★**`--add-dir`／`/add-dir`** | **Hole（`~/Desktop/Hole`）を別ディレクトリとして追加できる。** 現在は Read 権限だけ許可している状態 |
| **音声入力（`/voice`・macOSは fn×2）** | **タイピングの約3倍速く、より詳しいプロンプトになる**とされる。★**本人は日本語で長文を書く場面が多い＝相性が良い可能性** |
| **`/statusline`** | 残りコンテキスト・コストを常時表示 |
| **`/simplify`** | 変更後に並列レビューエージェントが「再利用・品質・効率・CLAUDE.md準拠」を点検する |
| ⚠️**`/loop`・`/schedule`（定期実行）** | ❌**使わない。** 社不ライフの教訓4＝**無人の自動化が保守負荷と事故でキャパを食い、休眠の決定理由になった。** データ保全（gitバックアップ）以外は自動化しない |
