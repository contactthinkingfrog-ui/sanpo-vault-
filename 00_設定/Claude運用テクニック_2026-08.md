# Claude運用テクニック

---

## §1 ★★★最重要の発見＝**CLAUDE.mdが長すぎることが、8回撤回の機械的な原因**

公式ドキュメントに、そのままの記述がある：

> **「CLAUDE.mdが長すぎると、Claudeは半分を無視する。重要なルールがノイズに埋もれるから。」**
> **「Claudeがルールに反することを繰り返すなら、たいていファイルが長すぎて、そのルールが埋もれている。」**
> **「肥大したCLAUDE.mdは、Claudeが実際の指示を無視する原因になる。」**

**この保管庫で起きたこと：**

| | |
|---|---|
| **CLAUDE.md の長さ** | **227行** |
| ルール | 「**発見を1つ得たら、結論に飛ぶ前に確定事項と突き合わせる**」＝**書いてある** |
| 実際 | ★**2026-08-03に1セッションで8回撤回。自分で気づいたものはゼロ** |

> ★**「Claudeが気をつける」で直そうとしていたが、公式の診断は「ファイルが長すぎるから埋もれている」。**
> ★**そして対策も書いてある＝「常に必要な事実」だけCLAUDE.mdに残し、「たまにしか要らない手順」はスキルに出す。スキルは使うときだけ読み込まれるので、普段のコストがゼロ。**

### 1-1. 公式が言う「CLAUDE.mdに入れるもの／入れないもの」

| ✅入れる | ❌入れない |
|---|---|
| Claudeが推測できないコマンド | 読めばわかること |
| 既定と違うルール | 標準的な慣習 |
| **プロジェクト固有の決定事項** | **詳細なドキュメント（リンクにする）** |
| よくある落とし穴・非自明な挙動 | 長い説明・チュートリアル |
| リポジトリの作法 | **頻繁に変わる情報** |

**判定基準＝「この行を消したらClaudeがミスをするか？ しないなら消す。」**

### 1-2. ★この保管庫のCLAUDE.mdを、この基準で仕分けると

| 現在の中身 | 判定 |
|---|---|
| **現在の状態（今どのSTEP・B2の結論）** | ⚠️**頻繁に変わる**＝公式の「入れない」に該当。**引き継ぎ書とロードマップが正なので、CLAUDE.mdはそこへのリンクだけでよい** |
| **決まっていること（本人決定）** | ✅**残す**（ただし引き継ぎ書§3と二重管理になっている） |
| **Claudeへの警告（8回撤回・掟）** | ✅**残す。むしろ埋もれないよう最上部に短く** |
| フォルダ構成 | ❌**読めばわかる**＝消す |
| YMYL区分の表 | ⚠️**日本語版の棚上げ資産。英語圏版では未使用**＝スキルへ |
| ワークフロー6種の表 | ⚠️**手順＝スキルへ** |
| 記事生成の6ステップ | ⚠️**手順＝スキルへ**（記事を書くときだけ要る） |
| トーン・文体ルール（暫定） | ⚠️**voice-guide-enと重複**＝リンクにする |
| 社不ライフとの関係 | ⚠️**教訓と資産に書いてある**＝リンクにする |

> ★**要点＝227行のうち、常時必要なのはおそらく50〜70行。残りは「記事を書くとき」「実装するとき」にだけ要る手順。**

## §3 その他の有効なテクニック（公式より）

| テクニック | この保管庫での使いどころ |
|---|---|
| ★**「Claudeにインタビューさせる」** | 「[お題]について、AskUserQuestionツールで詳細にインタビューして。実装・エッジケース・懸念・トレードオフを聞いて。当たり前のことは聞かず、私が考えていない難所を掘って。全部カバーしたらSPEC.mdに仕様を書いて」→ ★**B3（何を約束するか）に直接使える。** ※本セッションには `grill-me` スキルもある |
| **プランモード**（Shift+Tab） | 探索→計画→実行を分ける。**設計フェーズの今はほぼ常時これでよい** |
| ★**`/clear` を課題の切れ目で使う** | 「無関係な話題が混ざったセッション」は性能が落ちる。**★2回訂正しても直らなかったら、粘らずに `/clear` して、学んだことを入れた新しい指示で始める方が良い** |
| **サブエージェントで調査する** | 大量のファイルを読む調査は別コンテキストでやらせ、要約だけ受け取る。**⚠️本保管庫では本人の指示がない限り使わない** |
| **`@path/to/file` でCLAUDE.mdから他ファイルを読み込む** | CLAUDE.mdを薄くしつつ、必要な参照を保てる |
| **`/rewind`（Esc 2回）** | 失敗した試行を巻き戻す。**「危ないことを試して、ダメなら戻す」が安全にできる** |
| **セッションに名前をつける（`/rename`）** | 「B3-約束の一文」のように、作業単位ごとに名前を持たせる |
