# 実装規範（Opus向け）

## §1 Cocoonの罠（社不ライフ実証済み・ここでハマると数セッション溶ける）

1. 固定ページ/カテゴリ本文のHTMLは `wp:html` ブロックに入れていた。通常ブロックに貼ると wpautop が `<p>` を自動挿入してレイアウトが壊れる。
2. 繰り返し部品は Cocoonのテンプレート機能（`[temp id=X]`）で部品化（著者ボックス・NL導線・開示文など）。全記事に生HTMLをコピペしない＝後から一括変更できる形。
3. CSSは子テーマ `style.css` 一本。カスタマイザーの追加CSS・記事内 `<style>` に分散させると正本が割れる（過去の失敗）。
4. 表示検証はキャッシュ削除→ `curl` でHTML実体を確認してから見た目を見る（キャッシュ済みHTMLに騙された事故あり）。
5. カテゴリページの説明文はCocoonの「カテゴリ本文」機能（本文つきカテゴリ＝ハブ化）。
6. Cocoonの既存部品（自動目次・吹き出し）を使う。目次ブロックは手動で入れない。h1は本文に書かない（投稿タイトルがh1）。

## §2 CSS/HTML規約

- **デザイントークンは`:root`のCSS変数1箇所に集約**（色・書体・余白・罫線）。トークン名はTrack2で確定したデザインの語彙に従い、**値の直書きを部品CSSに散らさない**（＝デザイン差し替え耐性）。
- 命名＝`.tsh-`プレフィックス＋部品名（BEM的に浅く。例：`.tsh-cheat`、`.tsh-cheat__title`）。**ネスト・詳細度は浅く**、Cocoon上書きは読み込み順（子テーマが後勝ち）で解決。`!important` は使わない運用（使ったらコメントで理由）。
- モバイルファースト（`min-width`のメディアクエリのみ）。ブレークポイントは2つまで。
- HTMLはセマンティックに：`article`/`nav`/`figure`/`time`。装飾目的の `div` 多重ネストはしていない。部品は単体でコピペしても崩れない自己完結ブロック（WP運用の現実に合わせる）。
- JSはバニラ・最小限・プログレッシブエンハンスメント（JS無効でも全コンテンツが読める）。`defer` を付けていた。

## §5 実装の進め方（Track4の作業順・各ステップで止まって確認）

1. トークン＋ベースタイポ（本文だけのページで可読性確認）→ 2. 記事テンプレ部品（サンプル記事1本で全部品）→ 3. トップ/ハブ/カテゴリ → 4. 固定ページ → 5. Lighthouse計測→調整 → 6. 受け入れ基準（要件定義§5）を1項目ずつ潰す。
- 各ステップの成果はスクショ＋ファイルパスを activity.md に残していた。
- モックの本人承認（Track2）を経ていない見た目の独自変更はしていない。実装中に良いアイデアが出たら作らず activity.md に提案として書いていた（教訓1：装置を先に作らない）。
